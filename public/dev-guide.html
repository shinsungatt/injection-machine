1. 제작 배경 & 컨셉

1-1. 왜 만들었나

사출성형 공장에서 신규 RFQ(견적 요청)를 받으면 파트리스트를 보고 어떤 설비에 배정할지 수작업으로 판단해야 했다. 판단 기준이 사람마다 다르고, 엑셀로 계산하더라도 오류가 잦으며, 설비 스펙을 매번 찾아보는 과정이 비효율적이었다.

자동화 목표: 파트번호·재료·중량·투영면적·캐비티수만 입력하면 형체력·사출량·금형크기 3가지 조건을 자동으로 계산해 가장 적합한 설비를 1~3순위로 추천.

1-2. 핵심 컨셉

  • 현장 공식의 코드화 — 엔지니어가 머릿속에서 하던 계산(투영면적×수지압력×캐비티/1000×1.2)을 그대로 TypeScript로 구현
  • 엑셀 → 웹 전환 — 기존 엑셀 BOM 파일을 그대로 드래그 드롭 업로드 → 자동 파싱 → DB 저장
  • 활용률 최적화 — 단순히 "들어가는 설비" 찾기가 아니라 형체력 활용률 60~85%라는 실무 기준으로 최적 선택
  • 사이클 타임 예측 — 두께 기반 물리공식(냉각시간)과 경험식을 블렌딩해 C/T 자동 예측
  • Safety Guard 중심 설계 — 입력 데이터가 불완전해도 이상값이 나오지 않도록 클램핑·기본값 적용

1-3. 사용 시나리오

  1. 고객사로부터 RFQ Excel(파트리스트) 수신
  2. 앱에 파일 업로드 → 자동 파싱 저장
  3. "설비 추천 계산" 클릭 → 파트별 1~3순위 설비 즉시 표시
  4. 결과 Excel 내보내기 → 견적서/보고서에 바로 활용

3-4. notes 필드 설계 패턴

// notes 필드에 key:value 형식으로 여러 정보 저장
"thickness_mm:2.5|finish:high_gloss|slide:true"

// 파싱 함수로 추출

⚠️ 주의사항 notes 필드는 편리하지만 검색/정렬이 불가능하다. 자주 조회하거나 필터링이 필요한 값은 별도 컬럼으로 분리해야 한다.

4. 핵심 알고리즘 상세

4-1. 형체력(Clamping Force) 계산

필요 형체력(ton) = 투영면적(cm²) × 수지압력(kgf/cm²) × 캐비티수 ÷ 1000 × 안전율
  • 안전율: 일반 1.2, 슬라이드 구조 1.3
  • PC+ABS + High Glossy 표면처리: 수지압력 450 → 600 kgf/cm²
재질수지압력(kgf/cm²)사출량 보정계수밀도(g/cm³)
PP3001.1540.91
ABS3501.0001.05
PA66/PA4000.9211.14
PC4500.8751.20
PC+ABS450 (HG:600)0.8751.15
POM3500.7391.42
TPE/TPU3001.1670.90

4-2. 사출량(Shot Weight) 계산

필요 사출량(g) = (파트중량 × 캐비티수 + 런너중량) ÷ 0.8 × 재료보정계수

런너 미입력 시 기본값: 파트중량 × 0.15

4-3. 설비 추천 순위 알고리즘

  1. 3가지 조건 모두 충족하는 설비만 후보 선정
      • 형체력: 필요 ≤ 설비 보유
      • 사출량: 필요 ≤ 설비 보유
      • 금형 크기: 타이바 간격 이내
  2. 형체력 활용률 60~85% 범위인 설비 최우선
  3. 같은 범위 내에서 70%에 가장 가까운 순으로 정렬
  4. 1~3순위 부여, DB 저장

4-4. C/T 예측 — 두께 기반 물리 공식

CT = (t_eff² × k_cool) + T_dry + 캐비티 보정

단계별 로직:

  1. 두께 취득 Priority 1: 사용자 직접 입력 (Max Wall Thickness 필드)
  2. 두께 취득 Priority 2: 중량/밀도/투영면적으로 역산
    rawMm = (중량 ÷ 밀도 ÷ 투영면적) × 10
  3. Safety Guard:
    • 역산값 > 4mm → 4mm 클램프
    • 직접 입력값 ≥ 5mm → 3.5mm 강제 고정 (제품 높이 오기입 방지)
  4. 유효 두께: t_eff = rawMm × 0.82 (리브/보스 체적 분산 보정)
  5. 블렌딩: rawMm 1.5~4.0mm 구간에서 물리식·경험식 선형 보간
재질냉각계수 k드라이 사이클 기준
PC+ABS1.7형체력에 따라 18~40초
PC2.0동일
PP1.2동일
ABS1.4동일
PA661.3동일
⛔ 300초 오류 재현 조건 (v1.0.0 버그) PC+ABS 100g, 면적 5cm², 두께 미입력
역산: rawMm = (100÷1.15÷5)×10 = 173mm → t_cool = 173²×1.7 = 50,879초 → 300초(상한)
v1.1.0 수정 후: rawMm = min(173, 4) = 4mm → t_cool = 3.28²×1.7 ≈ 18초 → CT ≈ 45초 ✓

6. 트러블슈팅 전체 이력

Git 커밋 기준, 실제로 발생한 버그와 해결 방법을 시간 순으로 정리.

  • FIX
    설비 데이터 로드 오류 / Vercel 환경변수 미설정
    로컬에서는 동작하지만 Vercel에서 Supabase 연결 실패.
    원인: .env.local이 git에 포함되지 않아 Vercel에 환경변수가 없었음.
    해결: Vercel Dashboard → Settings → Environment Variables에 NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_ANON_KEY 수동 등록.
  • FIX
    도면 파일 업로드 후 카드에 미표시
    파일 업로드 성공 후 페이지 새로고침을 해야만 카드에 파일이 표시됨.
    원인: 업로드 완료 후 state 업데이트를 하지 않고 router.refresh()만 호출.
    해결: 업로드 후 파일 목록 fetch API 다시 호출하여 로컬 state 갱신.
  • FIX
    투영면적 빈칸 허용 / 제품 사이즈 자동 계산 미작동
    투영면적을 직접 입력하지 않으면 필수 입력 오류 발생. 제품 가로×세로로 자동 계산되어야 하는데 동작 안 함.
    원인: form validation이 projected_area_cm2를 항상 required로 처리.
    해결: submit 시 투영면적이 0이면 product_width × product_height로 재계산 후 사용.
  • FIX
    현대 RFQ Excel 2줄 헤더 파싱 실패
    실제 현대자동차 RFQ 양식은 헤더가 2행으로 구성되어 있어 1행 기준 파싱 시 매핑 실패.
    원인: xlsx 파싱 시 첫 번째 행을 헤더로 고정 처리.
    해결: 헤더 자동 감지 로직 추가 — 숫자 비율이 높은 행을 데이터 시작행으로 판별. 빈칸/합셀 스킵.
  • FIX
    WOORY XV1 Excel 매핑 버그 — 투영면적·캐비티 오매핑
    특정 고객사 엑셀에서 투영면적 열과 캐비티수 열이 뒤바뀌어 계산 결과 이상.
    원인: 컬럼 헤더 키워드 매핑 우선순위 충돌. "면적" 키워드가 다른 컬럼에도 부분 매칭됨.
    해결: 매핑 키워드를 정확도 순으로 우선순위화. "투영면적", "proj" → "면적" 순서로 우선 매칭.
  • FIX
    캐비티 매핑 누락 + 비사출 재질 필터링 미작동
    캐비티 수가 항상 1로 저장. "도장", "가죽" 등 비사출 부품이 파트 목록에 포함되어 계산 오류.
    원인: 캐비티 헤더 키워드에 "cav" 대소문자 미처리. 비사출 재질 필터 로직 누락.
    해결: 대소문자 무관 키워드 매칭. 비사출 재질(도장, 도금, 가죽, 직물 등) 업로드 단계에서 자동 제외.
  • FIX
    로그아웃 미작동 — HttpOnly 쿠키 문제
    로그아웃 버튼 클릭 시 페이지는 이동되나 새로고침하면 다시 로그인 상태.
    원인: 클라이언트에서 supabase.auth.signOut()만 호출하면 서버사이드 HttpOnly 쿠키가 지워지지 않음.
    해결: /api/auth/signout API Route 생성 → 서버에서 쿠키 삭제 후 리다이렉트.
  • FIX
    자동 로그인 시 관리자 메뉴 안 보임 — role 상태 Race Condition
    페이지 첫 로드 시 잠깐 일반 사용자 UI가 보였다가 관리자 메뉴가 나타나는 깜빡임 현상.
    원인: AuthProvider가 클라이언트에서 auth 상태를 비동기로 가져오는 동안 role이 null.
    해결: 서버 컴포넌트에서 초기 auth 상태(user + role)를 미리 가져와 AuthProvider에 prop으로 전달. 클라이언트 상태 초기값을 서버값으로 세팅.
  • FIX
    관리자 승인 시 이메일 인증 충돌
    관리자가 사용자를 승인해도 Supabase 이메일 인증이 안 된 상태면 로그인 불가.
    원인: Supabase Auth 기본 설정이 이메일 인증 필수. 승인제와 이메일 인증이 이중으로 걸림.
    해결: 관리자 승인 API에서 Supabase Admin API로 email_confirmed_at을 현재 시각으로 강제 설정.
  • FIX
    C/T 예측값 300초 오류 — 두께 역산 폭발
    두께를 입력하지 않으면 C/T가 300초(상한)로 계산되는 버그.
    원인: 중량이 크고 면적이 작은 파트의 경우 역산 두께가 수십mm로 계산됨 → t²×k가 수만초 → 상한 300초.
    예시: 100g, 5cm², 밀도 1.15 → rawMm = 173mm → 50,879초
    해결: 역산값을 Math.min(rawMm, 4.0)으로 클램프. 직접 입력값도 ≥5mm면 3.5mm 고정.

8-2. Supabase 관련 주의사항

상황주의사항
인증 쿠키서버사이드 로그아웃은 반드시 API Route에서 쿠키 직접 삭제. 클라이언트 signOut()만으로는 HttpOnly 쿠키 미삭제.

8-3. Excel 업로드 구현 패턴

// 고객사마다 헤더 형식이 다를 때 키워드 매핑 패턴
const HEADER_MAP = {
  part_number:       ['파트번호', 'part no', 'part_number', 'p/n'],
  projected_area_cm2:['투영면적', 'proj area', 'projected area'],
  cavity_count:      ['캐비티', 'cav', 'cavity'],
  // ...
}

function findColumn(headers: string[], field: string): number {
  const keywords = HEADER_MAP[field]
  return headers.findIndex(h =>
    keywords.some(kw => h.toLowerCase().includes(kw.toLowerCase()))
  )
}
// 주의: 우선순위가 높은 키워드를 배열 앞에 배치
// "투영면적" → "면적" 순서 (짧은 키워드가 다른 컬럼에 오매핑될 수 있음)

8-4. Safety Guard 설계 원칙

사용자 입력 데이터는 항상 이상값을 가정하고 방어 코드를 작성한다.

// 패턴: Clamp + Default + Warn
function safeValue(input: number | null, min: number, max: number, defaultVal: number): number {
  if (input === null || isNaN(input)) return defaultVal
  if (input > max) return max   // Clamp
  if (input < min) return min
  return input
}

// 적용 사례
const thickness = safeValue(inputThickness, 0.5, 4.0, 2.5)
const area = safeValue(inputArea, 1, 10000, 0)  // 0이면 형체력 계산 스킵

8-5. 알고리즘 파일 관리 원칙

  • 물리/공학 공식은 주석에 출처·단위·검증 예시를 반드시 기록
  • 재질별 상수 테이블을 별도 Record<string, number> 객체로 분리 (유지보수 용이)
  • 공식 검증값을 JSDoc 주석에 포함: // PC+ABS 18g / 42.84cm² → 33초 (이론 33.3초)
  • Safety Guard 상수는 이름 있는 상수로 선언: const THICKNESS_CLAMP_MAX = 4.0

9-1. 개발 철학

원칙설명구현 예시
현장 공식 우선 이론보다 현장에서 실제로 쓰는 계산식을 코드화. 복잡한 모델보다 단순하고 설명 가능한 공식. 형체력 = 투영면적×수지압력×캐비티/1000×1.2 (교과서 공식)
데이터 불완전성 대비 현장 데이터는 항상 일부가 빠져 있다. 미입력 필드는 오류 대신 기본값·역산으로 처리. 두께 미입력 → 중량/면적 역산 → 4mm 클램프
이상값 방어(Safety Guard) 계산 결과가 물리적으로 불가능한 값이 나오지 않도록 반드시 상한/하한 설정. CT = max(15, min(300, ct)), rawMm = min(rawMm, 4.0)
출처 투명성 예측값과 실측값을 명확히 구분 표시. 사용자가 결과를 믿을 수 있게. "33sec (예측)", "45sec (실측)", 두께 "역산 2.3mm [클램프]"
엑셀 친화성 사용자들이 엑셀로 일하는 환경. 업로드·내보내기 모두 xlsx 지원. Excel 업로드 → 자동 파싱, 결과 Excel 내보내기 (3시트)
